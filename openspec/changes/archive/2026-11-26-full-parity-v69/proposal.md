# Proposal

## Why

Релиз `v69.0.0` закрыл ключевые игровые сценарии, но не обеспечил полного паритета с v68: часть UX и сервисных возможностей потеряна, данные v68 не переносятся, а production-деплой нового стека не подготовлен. Аудит показал 164 неиспользуемых ключа локализации и отсутствие как минимум 16 интерактивных элементов v68. Это мешает полностью отказаться от legacy-стека и делает релиз v69 преждевременным с точки зрения функциональной полноты.

## What Changes

- Демо по одной кнопке снова открывает полноценный дашборд с участниками, жеребьёвкой и чатом; в v69 кнопка ведёт только в быструю жеребьёвку.
- Локальная игра без сервера: комнаты, жеребьёвка, вишлисты, чат и журнал продолжают работать офлайн и не теряют данные при отсутствии API.
- Групповые исключения «сугроб» получают интерфейс создания и удаления; API уже хранит `groupName`, но UI отсутствует.
- Организатор может добавлять и удалять участников комнаты напрямую; сейчас доступен только вход по приглашению.
- Push-подписки, тестовое уведомление и напоминания за 3/1/0 дней до события переносятся в новый стек вместе с реальной отправкой Web Push через VAPID на Node.js.
- Интерактивные гиды сайта и комнаты, пресеты и чипы идей, глобальные уведомления и модальное подтверждение разрушительных действий переносятся с адаптацией под Mantine и TanStack Router.
- Дашборд возвращает раскрытие получателя по кнопке, прогресс-бар, чеклист, обратный отсчёт, метаданные комнаты и читаемый журнал событий вместо сырых `event.type`.
- Чат возвращает шаблоны сообщений, подписи автора/времени и состояние отправки, а также блокировку до жеребьёвки.
- Приглашения получают готовый текст и кнопки Telegram / WhatsApp / Email; список сессий показывает агент, последний вход и текущую сессию с обновлением по кнопке.
- Установка PWA получает подсказки iOS/generic, карточку в футере и обновление при смене языка.
- Создание комнаты снова требует дату события и передаёт тему; быстрая жеребьёвка получает персональную ссылку для каждой пары, регистронезависимую проверку дубликатов, кириллический заголовок CSV и параметр `?gift=`.
- Восстанавливаются совместимые контракты API: верхний регистр кодов, `404 room_not_found`, ограничение частоты запросов, точный SSE-реплей по `Last-Event-ID` и единые имена событий.
- Добавляется перенос данных из `backend/data/app.db` в БД v69 с перевыпуском токенов и рабочие артефакты production-деплоя (`Dockerfile`, compose, health checks) для Hono API и SSR-приложения.
- Браузерные проверки v68 расширяются до сценариев v69; старый стек остаётся эталоном до завершения паритета.

## Capabilities

### New Capabilities

- `demo-and-local-play`: демо-игра в один клик и полноценная локальная игра без сервера на новой архитектуре.
- `push-notifications`: подписка, тест и автоматические напоминания о событии, включая Web Push.
- `guided-ux`: интерактивные гиды, подсказки-пресеты, уведомления, подтверждения и информативные панели дашборда.
- `data-migration`: перенос существующих данных v68 в хранилище v69 без потери доступов.
- `production-deployment`: воспроизводимый запуск API и веб-приложения v69 в production.

### Modified Capabilities

- `room-gameplay`: групповые исключения, управление участниками, приватное раскрытие, чат, приглашения и быстрая жеребьёвка.
- `pwa-offline`: офлайн-игра целиком и подсказки установки вместо только оболочки и очереди сообщений.

## Impact

- `apps/api`: новые эндпоинты участников и демо, VAPID/Web Push, воркер напоминаний, исправления контрактов и SSE, миграции.
- `apps/web`: локальный адаптер данных, демо-маршрут, новые панели и действия, провайдер Mantine Notifications, гиды, модалки и подсказки установки.
- `packages/shared`: контракты локальной игры, демо и push; активация 164 неиспользуемых ключей и новые ключи уведомлений.
- `packages/art`: переиспользование существующих 36 сцен в новых экранах без новых растровых ассетов.
- Инфраструктура: `Dockerfile` для API и web, compose, `.env.example`, скрипт миграции, CI и документация.
- Тесты: unit-тесты API/shared и расширенный Playwright-набор для v69.
