# server-rendering Specification

## Purpose

Определяет поведение серверного рендеринга: какие страницы приходят готовой HTML-разметкой, как подключаются стили и метаданные, и как происходит гидратация в браузере.

## Requirements

### Requirement: Серверный HTML для публичных страниц

Система MUST отдавать главную страницу и страницу входа с готовой разметкой, метаданными и основным содержимым до загрузки JavaScript.

#### Scenario: Первый запрос главной страницы

- **WHEN** браузер запрашивает `/`
- **THEN** сервер возвращает HTML с заголовком, описанием, навигацией и видимым содержанием первого экрана

#### Scenario: Прямой переход в комнату

- **WHEN** браузер запрашивает `/room/<code>` напрямую
- **THEN** сервер возвращает HTML с корректными метаданными комнаты и загружает данные через серверный загрузчик

### Requirement: Стили до гидратации

Система MUST подключать стили Mantine и приложения через тег `link` в `head`, чтобы не было вспышки нестилизованного содержимого.

#### Scenario: Загрузка страницы при медленном JS

- **WHEN** JavaScript ещё не загружен
- **THEN** страница уже отображает типографику, сетку и цвета темы из подключённых таблиц стилей

### Requirement: Гидратация без потери состояния

Система MUST гидратировать серверную разметку в интерактивное React-дерево без повторной замены видимого содержимого.

#### Scenario: Переход к интерактивности

- **WHEN** клиентский бандл выполняется
- **THEN** элементы управления становятся рабочими, а текст и изображения остаются на месте

### Requirement: Маршрутизация без hash

Система MUST использовать настоящие пути TanStack Router и поддерживать прямые переходы по ним.

#### Scenario: Обновление страницы комнаты

- **WHEN** пользователь обновляет страницу `/room/SANTA-1234`
- **THEN** сервер снова отдаёт ту же страницу с тем же путём, без редиректа на `/#dashboard`
