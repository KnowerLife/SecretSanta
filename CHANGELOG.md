# Changelog

Все значимые изменения фиксируются здесь. Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [Semantic Versioning](https://semver.org/lang/ru/).

## [Unreleased]

## [9.5.0] — 2026-11-26

### Added

- Статическая витрина на GitHub Pages: prerender главной и страниц create/join/quick-draw, SPA-fallback для неизвестных путей и понятная заглушка для комнат, которым нужен API.
- Англоязычный `README.en.md` с переключателем языка на главной странице репозитория; RU/EN-описание приводит демо и полный стек к одним сценариям.
- Ссылки в футере: copyright ведёт в репозиторий проекта, отдельная ссылка — на профиль https://github.com/KnowerLife.

### Changed

- Final-релиз зафиксирован как `v9.5.0`; образы GHCR публикуются с тегом `95` вместе с `v9.5.0` и `latest`.
- Compose и `.env.example` по умолчанию используют образы с тегом `95`.

## [69.4.0] — 2026-11-26

### Added

- Все 36 SVG-сцен перерисованы как отдельные детерминированные композиции с уникальными описаниями; добавлен регрессионный тест уникальности.
- Праздничный слой без внешних ассетов: мерцающие звёзды, два слоя снега, мягкие свечения и SVG-гирлянда с лампочками; анимации работают только на `transform`/`opacity` и отключаются при `prefers-reduced-motion`.
- Выбор темы при создании игры доступными карточками с `aria-pressed`; установка PWA появилась в табе «Люди» и в футере.

### Changed

- Обзор комнаты стал компактнее: внутренний переключатель «Пожелания / Профиль», инлайн-ввод желания и свёрнутые пресеты; блок «Как начать» оставлен на всю ширину.
- Таб «Люди» использует двухколоночную сетку с переходом в одну колонку на узких экранах; футер переработан с семантической навигацией и карточкой установки.

### Fixed

- Уведомления показывают текст сообщения и закрываются сразу по кнопке; добавлены локализованные доступные имена.
- `RoomGuide` и настройки начинаются с детерминированного состояния, поэтому сохранённые язык и тема больше не перезаписываются дефолтами при гидратации.
- Текст про приватность больше не примыкает к иллюстрации; выравнивание кнопок, табов и отступы секций приведены к единому ритму.

## [69.3.0] — 2026-11-26

### Added

- SVG-иллюстрации в гайде и быстрой жеребьёвке, декоративные снежинки в CTA и иконки trust-pills; все сцены получили уникальные идентификаторы при повторном использовании на странице.
- Compose больше не применяет HTTP-healthcheck API-образа к воркеру: воркер не слушает порт и теперь показывает корректный статус `Up` без ложного `unhealthy`.
- Публикация образов собирает `linux/amd64` и `linux/arm64`; образы доступны на хостах с Apple Silicon без принудительной замены платформы.

### Fixed

- `v69`: выравнивание всех страниц по легаси-композиции — геометрия Mantine-диалога (480px) и тостов (360px), фон шапки под тему, заголовок 20px/800, кнопки закрытия 44px, шрифт Manrope.
- Контраст текстового акцента в теме `midnight` (`--santa-accent-text`), подписи полей и шаги гайда приведены к общему ритму; инлайн-стили заменены классами.
- Гидратация страницы комнаты: сетевой статус теперь одинаков на сервере и клиенте, состояние `navigator.onLine` читается в эффекте.
- Кнопки закрытия диалога и уведомлений получили локализованные доступные имена; копия ID уведомления и переполнение панели приглашения на узких экранах устранены.
- Цвет метатеги браузерной панели следует активной теме; локальный баннер синхронизации, PWA-подсказка и страница 404 используют токены темы, текст 404 локализован.
- Обновлены инструкции по откату: в GHCR доступны `v69.3.0`, `v69.2.2` и `latest`, более старые теги требуют проверки через `docker manifest inspect`.
- Опубликованы образы API и web с тегом `v69.3.0` и `latest`; доступность манифестов проверена через `docker manifest inspect`.

### Removed

- Легаси-стек v68 удалён из репозитория: `index.html`, `app.js`, `src/*.js`, `styles.css`, `sw.js`, `backend/`, `assets/`, `icons/`, `docker-compose.yml`, `PRODUCTION_PLAN.md`, скриншоты и проверки v68. Для локальных регрессионных тестов сохранена игнорируемая копия `.legacy-v68-local/`.
- Легаси-workflow `.github/workflows/ci.yml` и связанные npm-команды (`verify:frontend`, `screenshots`) удалены; `Makefile` и `docs/RELEASES.md` теперь описывают только проверки v69.
- Устаревшие ветки `feature/*`, `hotfix/*` и `release/v69.0.0`–`release/v69.2.0` удалены с remote; остались `main`, `develop`, `release/v69.3.0` и все теги, включая `v69.2.2` для отката.

## [69.2.2] — 2026-11-26

### Fixed

- Нормализация владельца GHCR: шаг workflow больше не добавляет кавычки в имя образа, поэтому docker принимает теги `ghcr.io/knowerlife/...`.
- Тег образа по умолчанию обновлён до `v69.2.2`; теги `v69.2.0` и `v69.2.1` остаются неудачными попытками публикации и не рекомендуются для деплоя.

## [69.2.1] — 2026-11-26

### Fixed

- Публикация в GHCR использует владельца репозитория в нижнем регистре: docker отклонил тег `ghcr.io/KnowerLife/...` с ошибкой `repository name must be lowercase`.
- Тег образа по умолчанию обновлён до `v69.2.1`; тег `v69.2.0` остаётся как неудачная попытка публикации и не рекомендуется для деплоя.

## [69.2.0] — 2026-11-26

### Added

- Redis Pub/Sub для SSE между процессами API и воркером; курсор `Last-Event-ID` теперь берётся из `rowid` SQLite и переживает перезапуск.
- Workflow публикации образов в GHCR по тегу `v*` и вручную, с тегами версии и `latest`, а также документированная процедура отката через `V69_IMAGE_TAG`.
- Настраиваемая очистка журнала `room_events` и проверка подмены брокера события в unit-тестах.

### Fixed

- Браузерная проверка v69 завершает группу процессов локального API и веб-сервера: CI-задача больше не зависает после вывода `11 FAILED 0`.

### Changed

- SSE подписывается до replay, события дедуплицируются, кадр `connected` остаётся без `id`, а медленный клиент не блокирует остальные кадры.
- `/api/health`, `/api/push/config` и ответ на подписку используют единое состояние `pushEnabled()`; публичный ключ отдаётся только для корректной пары VAPID и допустимого `VAPID_SUBJECT`.
- compose поднимает Redis, передаёт `REDIS_URL` API и воркеру, а имена образов поддерживают `V69_IMAGE_REGISTRY` и `V69_IMAGE_NAMESPACE`.

### Security

- Production-старт API, воркера и миграции отклоняет отсутствующий, короткий или заглушечный `SECRET_SANTA_SECRET` до открытия порта.
- VAPID считается включённым только при совпадении публичного ключа с приватным; приватный ключ не попадает в логи и ответы API.

## [69.1.1] — 2026-11-26

### Fixed

- API-образ: в runtime добавлены исходники `@secret-santa/shared` и `apps/api/tsconfig.json`; сборка и запуск контейнера теперь работают.
- Проверены реальные `docker build`, `docker compose up`, healthcheck API, SSR через web-прокси и обработка задачи воркером; браузерные проверки v69 против compose — 10/10.

### Changed

- Тег образов по умолчанию обновлён до `v69.1.1` в compose, `.env.example` и инструкциях сборки.

### Security

- `postcss` обновлён с 8.5.6 до 8.5.33: `npm audit` сообщает о 0 уязвимостях.

v69.1.1 — рекомендуемая точка входа для деплоя. v68 остаётся эталоном и рабочим резервом.

## [69.1.0] — 2026-11-26

### Added

- Демо-комната в один клик, локальная игра без сервера и единый алгоритм жеребьёвки для локального и серверного режимов.
- Групповые исключения, добавление и удаление участников, готовые приглашения и список сессий.
- Web Push с тестовой отправкой и напоминаниями за 3/1/0 дней через отдельный воркер.
- Направляющий UX: гиды сайта и комнаты, пресеты пожеланий, индикаторы готовности, уведомления и подтверждения разрушительных действий.
- Перенос данных v68 → v69 с сохранением доступов, проверкой счётчиков и неизменностью источника.
- Docker-артефакты API и SSR, `docker-compose.v69.yml`, `.env.example` и документация деплоя.
- Дельта-спеки `full-parity-v69` перенесены в основные спеки, change архивирован.

### Changed

- Имя получателя раскрывается только явным действием участника; SSR не сериализует назначение.
- Статические стили Mantine подключены в SSR, runtime-стили отключены для совместимости с React 19.
- Словарь RU/EN расширен до 476 ключей, неиспользуемых ключей нет.
- Браузерные проверки v69 перенесены на порты 3000/8787 и дополнены Lighthouse для 3 тем × RU/EN.

### Fixed

- Гейты готовности Vite явно привязаны к `127.0.0.1`, а SSE-тест не ожидает `networkidle` при открытом соединении.
- Lighthouse использует Chromium Playwright через `CHROME_PATH`; доступность для трёх тем на двух языках — 1.00.

### Security

- Push-сообщения не содержат имён получателей, назначений или содержимого чата; подпись ES256 не передаёт конфиденциальный payload.

> Docker CLI в среде проверки недоступен: `docker build` и `docker compose up` не запускались. Конфигурация проверена статически и требует повторной проверки в среде с Docker.

На момент релиза v69.1.0 рекомендуемой точкой входа был этот выпуск; v68 остаётся эталоном и рабочим резервом.

## [69.0.0] — 2026-11-26

### Added

- OpenSpec-change `migrate-v69-ts-stack` с пятью capability: `room-gameplay`, `server-rendering`, `localized-themes`, `svg-scenes`, `pwa-offline`.
- npm workspaces: `apps/web`, `apps/api`, `packages/shared`, `packages/art`.
- `apps/web`: SSR на TanStack Start + Vite 8, TanStack Router/Query, Mantine 9, FSD-слои, RU/EN и три темы, PWA-манифест и service worker.
- `apps/api`: Hono + TypeScript + `node:sqlite`, HMAC-сессии и приглашения, комнаты, жеребьёвка, исключения, вишлисты, профили, активность, чат, SSE и уведомления.
- `packages/shared`: точный RU/EN-словарь, доменные контракты и чистый алгоритм derangement.
- `packages/art`: 36 детерминированных SVG-сцен с тремя палитрами и генератор статических файлов.
- Документация процесса: `docs/GITFLOW.md`, `docs/RELEASES.md`, `docs/PARITY_v69.md`, workflow `.github/workflows/ci-v69.yml`.

### Changed

- `package.json` расширен до workspaces при сохранении скриптов проверок v68.
- `README.md` дополнен разделом о параллельной разработке v69.

### Fixed

- Контраст текста во всех трёх темах v69: Lighthouse accessibility 1.00 для RU/EN × winter/midnight/cozy.
- Офлайн-очередь сообщений: параллельные слушатели `online` больше не отправляют одно сообщение дважды.
- SSR дашборда: токен комнаты хранится в отдельной cookie `ss_token_<CODE>`, поэтому несколько комнат не конфликтуют.

v69.0.0 — рекомендуемая точка входа для разработки. v68 сохранён как legacy-стек и резервный вариант; старые файлы и проверки не удалены. Production-деплой нового стека ещё не настроен.

## [68.0.0] — 2026-01-15

### Added

- Разделение frontend на 18 ES-модулей, серверная жеребьёвка, комнаты с SSE, анонимный чат, RU/EN, три темы и офлайн-очередь.

### Fixed

- Контраст темы `cozy` и версии ассетов/service worker обновлены до v68.
