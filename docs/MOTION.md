# Анимации интерфейса

В проекте есть собственные праздничные эффекты (`festive-*`) и небольшая подборка анимаций из [animate.css 4.1.1](https://github.com/animate-css/animate.css). Библиотека подключена как npm-зависимость, но в CSS импортируются **только исходники пяти используемых эффектов** — не весь 70 КБ-бандл:

```css
@import 'animate.css/source/_vars.css';
@import 'animate.css/source/_base.css';
@import 'animate.css/source/zooming_entrances/zoomIn.css';
/* ... */
```

Все подключения лежат в `apps/web/src/app/styles/motion.css`, длительности — в семантических классах `motion-*`.

## Токены движения

Кривые и длительности вынесены в `:root` (`apps/web/src/app/styles/global.css`): `--santa-ease-*`, `--santa-dur-*` и `--santa-delay-*`. Правила в `global.css` и `motion.css` содержат только ссылки на токены, поэтому тайминг меняется в одном месте. Каскад строк жеребьёвки использует `--santa-delay-stagger` и в CSS, и в inline-стиле строки, чтобы задержка не расходилась.

Идея взята из конфигов Hyprland (именованные кривые и дерево анимаций с общими значениями), но код и лицензия Hyprland в проект не попадают: он написан на C++ и под BSD-3-Clause, а здесь используется только подход. Декоративные `festive-*` циклы (снег, звёзды, гирлянда) оставлены с явными длительностями — они не участвуют в смысловых состояниях интерфейса.

## Что и зачем выбрано

| Эффект | Где используется | Почему именно он |
| :--- | :--- | :--- |
| `zoomIn` | Раскрытие карточки получателя (`RevealCard`) | Главный эмоциональный момент приложения. Масштаб от 0.3 подчёркивает «вот оно», не меняя порядок чтения. |
| `fadeInUp` | Строки результата быстрой жеребьёвки (`QuickDrawTool`) | Пары появляются каскадом с задержкой 70 мс (до 8 строк). Показывает, что результат новый, и даёт глазу точку входа. |
| `headShake` | Ошибки форм create/join/quick-draw | Мягкое отрицание вместо резкого `shake`: пользователь сразу видит, что заполнение не принято. Текст ошибки остаётся единственным источником смысла. |
| `fadeInDown` | Уведомления об успешном копировании/приглашении | Короткое подтверждение действия, не конкурирует с Mantine-тостами. |
| `pulse` | Строка «все шаги выполнены» в прогрессе | Едва заметное 1.05× поздравление один раз, без бесконечного цикла. |

Длительности подобраны под конкретный смысл: 320 мс для подтверждения, 420 мс для ошибки и строк, 620 мс для раскрытия, 800 мс для поздравления. Один тайминг на всё не используется.

## Чего намеренно нет

- `bounce`, `tada`, `wobble`, `jello`, `flash`, `rubberBand` — слишком шумно для интерфейса, где одновременно читают список и формы.
- `flip`, `lightSpeedIn*`, `hinge`, `jackInTheBox` — дезориентируют и мешают читать текст, особенно на мобильных.
- Exit-анимации — элементы в приложении не удаляются с анимацией; тосты и модалки управляются Mantine.
- Анимация всей страницы при смене роута — дублирует `festive-rise` на главной и увеличивает риск hydration-рассинхрона в SSR.
- Анимация каждого события в ленте активности — при SSE-пачке это превратилось бы в мигающий список.

## Доступность

- `prefers-reduced-motion: reduce` обнуляет длительность ещё в базовом классе animate.css; в `motion.css` дополнительно обнуляется `animation-delay`, чтобы строки результата не оставались скрытыми.
- Анимации не единственный способ передать информацию: у ошибок есть `role="alert"`, у уведомлений `role="status"`, у прогресса `role="progressbar"`.
- На одном экране анимируется не более одного-двух смысловых элементов; декоративные `festive-*` не несут информации.

## Как добавить ещё

1. Добавить `@import 'animate.css/source/<категория>/<эффект>.css';` в `motion.css`.
2. Завести семантический класс `motion-*` с длительностью под задачу.
3. Обновить таблицу выше и `scripts/motion.test.mjs`.
